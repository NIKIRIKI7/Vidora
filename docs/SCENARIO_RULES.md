# Правила составления сценария (SCENARIO.md) для Vidora

Файл `SCENARIO.md` является единым источником истины (SSOT) для проекта в Vidora. Он управляет метаданными, визуальным стилем и самим контентом (разбитым на сцены и фрагменты).

## 1. Frontmatter (Метаданные и Настройки)
Сценарий ДОЛЖЕН начинаться с YAML-блока, ограниченного `---`. Этот блок определяет глобальные параметры проекта и дизайн-систему (Remotion Composition).

Обязательные поля:
- `title`: Название ролика
- `description`: Описание для YouTube/соцсетей
- `fps`: Частота кадров (24, 30, 60)
- `animation_style`: Базовый стиль анимации (например, screencast, motion_cut, cinematic)
- Цветовая палитра: `primary`, `secondary`, `background`, `surface`, `accent`, `text` (в формате HEX).

**Пример:**
```yaml
---
title: "Обзор RTX 5090"
description: "Распаковка и тест новой видеокарты"
tags: [tech, review, rtx5090]
animation_style: motion_cut
fps: 60
primary: "#ddb7ff"
secondary: "#4fdbc8"
background: "#0b1326"
surface: "#171f33"
accent: "#ffb4ab"
text: "#dae2fd"
---
```

## 2. Структура сцен и фрагментов
Тело сценария состоит из **Сцен**, которые делятся на **Фрагменты**.

### Сцены
Сцена обозначается заголовком в квадратных скобках и примерным таймкодом в круглых скобках:
`[Название сцены] (Таймкод)`

### Фрагменты
Каждая сцена состоит из фрагментов. Фрагмент — это пара "Визуальная ремарка + Текст суфлера".
Визуальная ремарка пишется курсивом в скобках `*(текст)*`, сразу после нее идет текст, который будет озвучен ИИ (или спикером).

**Синтаксис фрагмента:**
`*(Визуальное описание для генерации кода или B-roll)* Текст для озвучки.`

**Пример:**
```md
[Вступление] (00:00:00)
*(Крупный план: логотип NVIDIA на черном фоне, камера наезжает)* Сегодня мы посмотрим на монстра.
*(График производительности, столбцы растут вверх, киберпанк стиль)* RTX 5090 разрушает все тесты.

[Распаковка] (00:00:15)
*(Камера сверху, коробка открывается)* Упаковка стала еще больше, весит почти 5 килограмм.
```

## 3. Правила парсинга (для разработчиков)
1. Если текст идет без `*(ремарки)*`, парсер автоматически назначает ему ремарку `A-roll: Без ремарок`.
2. Пустые строки между фрагментами игнорируются.
3. Таймкод `(00:00:00)` используется фронтендом для расчетов, но длительность каждого фрагмента может динамически пересчитываться после генерации аудио (OmniVoice).
