# Гайд по написанию сценария (SCENARIO.md)

`SCENARIO.md` — единственный источник правды (SSOT) для проекта в Vidora.
Vidora **парсит** этот файл и превращает в набор сцен с фрагментами. Всё,
что не описано в этом файле — не попадёт в видео. Всё, что описано —
попадёт как есть.

---

## 1. Frontmatter (YAML-шапка) — SEO и настройки

Между `---` задаются глобальные параметры проекта. Парсится регулярными
выражениями, так что **кавычки обязательны** для строк, квадратные скобки
для списков.

| Поле | Обязательно | Формат | Во что парсится |
|------|-------------|--------|-----------------|
| `title` | **да** | `"строка"` | `metadata.title` — заголовок видео, тег `<title>`, имя файла |
| `description` | нет | `"строка"` | `metadata.description` — мета-описание для YouTube/поисковиков |
| `tags` | нет | `[тег1, тег2]` | `metadata.tags` — массив тегов |
| `fps` | нет | `24`, `30` или `60` | `montage.fps` (по умолчанию `30`) |
| `animation_style` | нет | `screencast`, `motion_cut`, `cinematic`, `talking_head` | Стиль анимации Remotion |
| `transitions` | нет | `[fade, slide_left]` | Массив переходов между сценами |
| `primary` и др. | нет | `"#hex"` | Цвета палитры (6 ключей) |

### Правила для SEO-полей

- `title` — **строго одна строка в кавычках**. Длина: 30–60 символов
  (рекомендация YouTube). Без переносов.
  ```
  title: "Обзор RTX 5090: Стоит ли апгрейд?"
  ```
- `description` — одна строка в кавычках. 150–300 символов, содержит
  ключевые слова. Без Markdown.
  ```
  description: "Полный разбор RTX 5090: тесты в 4K, трассировка лучей, DLSS 4 и сравнение с 4090. Стоит ли ждать?"
  ```
- `tags` — квадратные скобки, через запятую, без кавычек вокруг тегов.
  До 10 тегов.
  ```
  tags: [nvidia, rtx5090, обзор, тест, gpu, 4k, gaming]
  ```

**Как Vidora парсит SEO:**
При импорте Markdown поля `title`, `description`, `tags` сохраняются в
`project.metadata`. При экспорте проекта (ZIP-архив) метаданные
вшиваются в YAML-шапку. При рендере HTML-страницы эти поля формируют
`<title>`, `<meta name="description">`, `<meta name="keywords">`.

### Цветовая палитра

6 цветов, каждый в формате `"#RRGGBB"` (обязательно в кавычках):

| Ключ | Назначение | Дефолт |
|------|-----------|--------|
| `primary` | Заголовки, акценты, кнопки | `#ddb7ff` |
| `secondary` | Субтитры, иконки | `#4fdbc8` |
| `accent` | Предупреждения, выделения | `#ffb4ab` |
| `background` | Фон сцены | `#0b1326` |
| `surface` | Карточки, панели | `#171f33` |
| `text` | Основной текст | `#dae2fd` |

Если не указаны — используются дефолтные.

### Переходы (transitions)

Список через запятую в `[]`. Если сцен больше, чем переходов —
последний повторяется.

| Значение | Визуал |
|----------|--------|
| `fade` | Плавное затухание |
| `slide_left` | Свайп влево |
| `slide_right` | Свайп вправо |
| `slide_up` | Свайп вверх |
| `zoom` | Наезд камеры |
| `glitch` | Цифровые помехи |
| `cross_zoom` | Кросс-зум |

### Полный пример YAML-шапки

```yaml
---
title: "Обзор RTX 5090: Стоит ли апгрейд?"
description: "Полный разбор RTX 5090: тесты в 4K, трассировка лучей, DLSS 4 и сравнение с 4090. Стоит ли ждать?"
tags: [nvidia, rtx5090, обзор, тест, gpu, 4k, gaming]
animation_style: motion_cut
fps: 60
transitions: [fade, slide_left]
primary: "#ddb7ff"
secondary: "#4fdbc8"
background: "#0b1326"
surface: "#171f33"
accent: "#ffb4ab"
text: "#dae2fd"
---
```

## 2. Структура сцены

Сценарий состоит из **сцен**. Каждая сцена начинается с заголовка:

```
[Название сцены] (MM:SS:MM)
```

- `[Название сцены]` — отображается в списке сцен и используется как
  имя файла при экспорте. Чем короче и понятнее — тем лучше.
- `(Таймкод)` — смещение начала сцены от начала видео. Форматы:
  `00:00:00` (чч:мм:сс), `00:00` (мм:сс), `00:00.00` (мм:сс.сотые).
  Таймкод может быть приблизительным — WhisperX скорректирует.

**Правила:**
- Между сценами — **пустая строка**.
- Таймкод обязателен в скобках (даже если `00:00:00`).
- Длина названия — 2-6 слов, без точки в конце.

### Фрагменты

Внутри сцены — **фрагменты**. Одна строка = один фрагмент:

```
*(Визуальная ремарка)* Текст, который читает TTS.
```

- `*(...)*` — **визуальная ремарка**. Описывает, что происходит на экране.
  Используется для генерации Remotion-компонента и подбора B-roll.
- `Текст после скобок` — **озвучка**. Читается TTS. Может быть пустым,
  тогда это чистый B-roll.

### Таймкод фрагмента (опционально)

Можно указать таймкод прямо в ремарке — он автоматически распарсится:

```
*(00:05 - 00:12: Крупный план рук)* Текст, синхронизированный с этим отрезком.
```

Формат: `MM:SS - MM:SS:` или `MM:SS.MS - MM:SS.MS:` перед текстом ремарки.

## 3. Визуальные ремарки: правила и типы

### Золотое правило

Ремарка описывает **то, что видно на экране**, а не то, что чувствует
зритель. Хорошая ремарка — конкретный кадр, плохая — абстракция.

```
✅ *(Крупный план: логотип появляется слева, текст выезжает справа)*
❌ *(Что-то крутое)*
✅ *(Анимация: график растёт снизу вверх, цифры меняются)*
❌ *(Эпично)*
✅ *(Текст на экране: «RTX 5090 — 4K 120 FPS»)*
❌ *(Впечатляюще)*
```

### Типы ремарок

Видос различает типы ремарок по первому слову после скобки:

| Шаблон | Для чего |
|--------|----------|
| `*(Экран: ...)*` | Скринкаст, интерфейс, код |
| `*(Крупный план: ...)*` | Деталь, лицо, объект крупно |
| `*(Средний план: ...)*` | Человек/объект в полный рост |
| `*(Анимация: ...)*` | Абстрактная анимация, переход |
| `*(Схема: ...)*` | Диаграмма, график, схема |
| `*(Текст на экране: ...)*` | Титр, заголовок, цитата |
| `*(Таймер: ...)*` | Обратный отсчёт, прогресc |
| `*(B-roll: ...)*` | Стоковый видеоряд (Pexels) |
| `*(00:00 - 00:00: ...)*` | Фрагмент с таймкодом |

Важно: тип ремарки влияет на промпт, который уходит в генерацию
Remotion-компонента. Для `B-roll` генерируется другой код, чем для
`Экран`.

### Пустой TTS (чистый B-roll)

Если после ремарки нет текста — фрагмент считается B-roll (без озвучки):

```
*(10-секундный таймлапс заката)*
*(Музыка нарастает, экран затемняется)*
```

## 4. Полноценный пример сценария

```md
---
title: "Обзор RTX 5090: Стоит ли апгрейд?"
description: "Полный разбор RTX 5090: тесты в 4K, трассировка лучей, DLSS 4 и сравнение с RTX 4090. Стоит ли ждать эту карту или брать 4090 сейчас?"
tags: [nvidia, rtx5090, обзор, тест, gpu, 4k, gaming]
animation_style: motion_cut
fps: 60
transitions: [fade, slide_left, zoom]
primary: "#ddb7ff"
secondary: "#4fdbc8"
background: "#0b1326"
surface: "#171f33"
accent: "#ffb4ab"
text: "#dae2fd"
---

[Хук] (00:00:00)
*(Экран: монтажная сетка с заголовком «5090 vs 4090», быстрые кадры игр в 4K)*
NVIDIA наконец-то выпустила RTX 5090. За $1999. Стоит ли брать? Давайте разбираться.
*(Крупный план: две видеокарты рядом, подсветка, сравнение размеров)*
В этом обзоре — тесты в 4K, трассировка лучей, DLSS 4 и честный вердикт.

[Технические характеристики] (00:00:15)
*(Схема: таблица с характеристиками 5090 vs 4090, подсветка ключевых отличий)*
RTX 5090 получила 21 760 ядер CUDA — на 33% больше, чем у 4090. Память — 32 ГБ GDDR7 на 512-битной шине.
*(Экран: график энергопотребления, столбцы TDP)*
TDP вырос с 450 до 575 ватт. Да, карта горячая. Но эффективность на ватт выросла на 20%.

[4K тесты] (00:00:32)
*(B-roll: Cyberpunk 2077 с трассировкой лучей, счетчик FPS в углу)*
В Cyberpunk 2077 с трассировкой лучей — 65 FPS в нативном 4K. 4090 выдаёт 42. Разрыв — 55%.
*(B-roll: Black Myth Wukong, сравнение сплитскин)*
Black Myth Wukong — 59 FPS против 38. DLSS 4 с генерацией кадров поднимает до 120 FPS.
*(Текст на экране: «DLSS 4 — эксклюзив 50 серии»)*
DLSS 4 работает только на 50-й серии. Модель Transformer — картинка чище, артефактов меньше.

[Трассировка лучей] (00:01:00)
*(Анимация: луч света отражается от поверхностей, сравнение RT-эффектов)*
Полная трассировка лучей (Path Tracing) — теперь играбельно. В 4090 было 25 FPS, в 5090 — 40.
*(Схема: диаграмма RT-производительности по играм)*
Alan Wake 2 с патч-трейсингом — 45 FPS против 28. Разрыв стабильный — 50–60% везде.

[Стоит ли брать?] (00:01:25)
*(Средний план: карта в сборе, подсветка, RGB-подсветка)*
Если у вас 4090 — апгрейд не обязателен. Смысл есть только если работаете с ML или рендерите 8K.
*(Крупный план: разъём питания, предупреждение о блоке питания)*
Если собираете ПК с нуля — 5090 берёт, но готовьте 1200W+ блок питания и хороший кейс.
*(Финальный кадр: логотип, ссылка на полный обзор, кнопка подписки)*
Ссылка на полный бенчмарк в описании. Подпишитесь, если было полезно. Всем удачного апгрейда!
```

## 5. Рекомендации по динамике (Pacing)

### Правило 4 секунд

Каждый фрагмент (одна визуальная ремарка) должен удерживаться **не
дольше 4 секунд**. Если зритель видит один кадр дольше — внимание падает.

| Длина фрагмента | Вердикт |
|-----------------|---------|
| 1–4 секунды | 🔥 Динамично |
| > 4 секунд | 🐌 Скучно |

**Как измерить:** Vidora автоматически считает pacing для каждой сцены
(длительность / количество фрагментов). Если таймкодов нет — длительность
оценивается по тексту (≈ 2.5 слова в секунду).

**Как исправить:** разбить длинный фрагмент на два-три, добавив новую
ремарку. Скопировали сцену → попросили ИИ разбить → вставили обратно.

### Целевые метрики

| Формат | Длина видео | Фрагментов |
|--------|------------|------------|
| YouTube (16:9) | 2–8 минут | 30–120 |
| Shorts (9:16) | 15–60 секунд | 5–15 |

### Структура хорошего сценария

1. **Хук** (первые 5 секунд) — зацепить внимание: вопрос, факт, интрига
2. **Проблема** (10–20% времени) — контекст, почему это важно
3. **Решение** (60–70% времени) — основное содержание, аргументы, тесты
4. **Вывод** (10–15% времени) — резюме, CTA, ссылки

Каждая сцена — ровно один микро-вывод. Зритель должен запомнить
одну мысль из каждой сцены.

## 6. Форматы и разрешения

Формат, разрешение и FPS задаются в UI (Настройки проекта, кнопка ⚙️),
но также могут быть указаны в YAML-шапке для переносимости:

| Поле | Формат | Пример |
|------|--------|--------|
| `fps` | `24`, `30`, `60` | `fps: 60` |

Формат (`16:9` / `9:16`) и разрешение (`1080p` / `1440p` / `2160p`)
задаются **только в UI**, в YAML они игнорируются.

| Формат | Разрешения | Платформы |
|--------|-----------|-----------|
| `16:9` | 1920×1080, 2560×1440, 3840×2160 | YouTube, Vimeo |
| `9:16` | 1080×1920, 1440×2560, 2160×3840 | Shorts, Reels, TikTok |

## 7. Импорт и экспорт сцен (мост с ИИ)

Vidora умеет копировать отдельные сцены в буфер обмена и вставлять их
обратно. Формат — ровно та же структура, что и в общем сценарии:

```
[Название сцены] (00:00:00)
*(Визуальная ремарка)* Текст суфлёра.
```

**Как работает мост:**
1. Навели на сцену → нажали копирование → Markdown в буфере
2. Вставили в ChatGPT/Claude: "Разбей на больше кадров, pacing < 4 сек"
3. Скопировали ответ → нажали вставку на той же сцене

**Валидация:**
- При вставке парсер проверяет формат `[Название](таймкод)`
- Если формат не совпадает — Vidora покажет ошибку и не тронет сцену
- Таймкод и название из буфера полностью заменяют старые

## 8. Что парсится, а что нет

| Элемент | Парсится? | Куда |
|---------|-----------|------|
| `---\n...\n---` | ✅ YAML шапка | `metadata`, `montage` |
| `[Название](таймкод)` | ✅ Заголовок сцены | `Scene.title`, `Scene.timecode` |
| `*(Ремарка)* Текст` | ✅ Фрагмент | `SceneFragment.visualNote`, `SceneFragment.text` |
| `*(00:00 - 00:00: ...)*` | ✅ Фрагмент с таймкодом | `startTime`, `endTime` |
| Пустая строка после `*(...)` | ✅ B-roll без текста | `text: ""` |
| `#`, `##`, `- ` списки | ❌ Игнорируется | — |
| `**жирный**`, `*курсив*` | ❌ Игнорируется | — |
| Ссылки `[текст](url)` | ❌ Игнорируется | — |
| Всё до первого `[` (кроме YAML) | ❌ Игнорируется | — |

Vidora игнорирует любой Markdown-форматирование внутри текста:
жирный, курсив, ссылки, списки, заголовки. Текст фрагмента идёт в TTS
как есть, без разметки. Ремарка тоже идёт как plain text в промпт
Remotion. Никакой лишний синтаксис не парсится и не ломает парсер.
